## 🎯 深度案例分析

### 问题1: 图谱检索系统未生效 (影响19个查询)

#### 典型案例

**案例A: 组织架构查询**

```yaml
查询: "销售部出差最多的员工是谁？"
期望检索类型: GRAPH (知识图谱查询)
期望结果: 从Neo4j图谱中查询出差记录统计

实际检索到的内容:
  - "销售部门销售总监：黄伟，向副总经理王芳汇报..."
  - "Q8：销售总监黄伟和市场总监周静是什么关系？..."
  - "人力资源部共有20人..."

问题诊断:
  ✗ 检索类型错误: 期望图谱查询，但返回了向量检索的规则文档
  ✗ 结果重复: 5个结果中只有4个是唯一的
  ✗ 无法回答问题: 检索结果包含组织架构，但没有出差统计数据
```

**案例B: 统计查询**

```yaml
查询: "过去3个月有多少次出差到北京？"
期望检索类型: GRAPH (时间范围 + 地点 + 统计)
期望结果: 从图谱中聚合出差记录

实际检索到的内容:
  - "☐出差 ☐驻外... 目的地点..."（表格HTML片段）
  - 重复的表格片段 × 5

问题诊断:
  ✗ 检索类型错误: 期望图谱聚合查询
  ✗ 结果重复严重: 5个结果中只有2个唯一
  ✗ 无结构化数据: 返回的是空表格模板，不是实际数据
```

#### 根本原因

1. **路由器未生效**: `intelligent_router` 没有正确识别图谱查询
2. **图谱检索器未调用**: 所有查询都走了默认的向量检索
3. **图谱数据可能缺失**: Neo4j中可能没有业务数据（只有规则文档）

### 问题2: 多跳推理查询 (影响3个查询)

#### 典型案例

```yaml
查询: "去北京出差3天，预计住宿和伙食费用是多少？"
期望检索类型: HYBRID (需要多个信息片段)
需要的信息:
  1. 北京住宿标准: 500元/天
  2. 伙食补助标准: 100元/天
  3. 计算: (500 + 100) × 3 = 1800元

实际检索到的内容:
  - "出差人员的住宿费在上述标准内凭票据报销..." × 2
  - "工作人员在市内三区执行公务..."

问题诊断:
  ✗ 关键词缺失: "北京"、"500"、"100"都未出现
  ✗ 检索到表格尾部: 没有检索到表格内容，只检索到</table>标签
  ✗ 单次检索不足: 需要2个独立的标准 + 计算能力
```

#### 根本原因

1. **表格结构问题**: 表格被截断，只检索到表格结束标签
2. **多信息需求**: 需要同时检索"住宿标准"和"伙食标准"
3. **缺少推理能力**: 检索后还需要LLM进行计算

### 问题3: 长尾查询 (影响1个查询)

#### 典型案例

```yaml
查询: "去西藏出差，6-9月住宿标准是多少？"
期望检索类型: VECTOR (但包含特殊条件组合)
期望关键词: ["西藏", "6-9月", "530"]

实际检索到的内容:
  - "第十一条 出差人员应当在职务级别对应的住宿标准限额内..." × 3

问题诊断:
  ✗ 关键词完全缺失: "西藏"、"6-9月"、"530"都未出现
  ✗ 检索到通用条款: 而不是具体的地区+季节标准
  ✗ 长尾组合: "地点 + 季节"的组合在训练数据中可能较少
```

#### 根本原因

1. **复合条件查询**: "西藏" AND "6-9月" 的组合相似度不足
2. **表格数据分块问题**: 淡旺季标准可能在单独的表格中，没有被正确索引
3. **Embedding语义理解**: 通用模型对"6-9月"这种时间表述的理解不足

## 📋 为什么FUSION没有改进？

### 当前FusionRetriever的配置

```python
# tests/evaluation/analyze_recall_failures.py:104
retriever = FusionRetriever([
    vectorstore.as_retriever(search_kwargs={"k": 5}),
])
```

### 问题分析

1. **只有一个检索器**: FusionRetriever只配置了一个向量检索器
2. **无融合意义**: 单个检索器的融合就是它自己
3. **应该添加的检索器**:
   - GraphRetriever (图谱检索)
   - BM25Retriever (关键词检索)
   - HybridRetriever (稠密+稀疏)

### 正确的FUSION配置

```python
retriever = FusionRetriever([
    vectorstore.as_retriever(search_kwargs={"k": 5}),  # 向量检索
    BM25Retriever.from_documents(documents),           # 关键词检索
    graph_retriever,                                    # 图谱检索
])
```

**预期效果:** 
- BM25可以补足向量检索对精确关键词的弱项
- 图谱检索可以处理统计和关系查询
- 融合后召回率可能从47.7% → 60%+
