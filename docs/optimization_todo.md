## 🔥 高优先级优化

### 1. RAG 检索优化 - 父子分块改造 ⏳

**当前问题**：
- 使用固定窗口切分（512 tokens + 50 overlap）
- 召回的文档块上下文不完整，导致答案质量不佳
- 例如查询"高管补贴标准"只返回"670 元/天"，缺少城市系数、审批流程等关键信息

**优化方案**：引入父子分块（Parent-Child Chunking）
- **子块**：256 tokens，用于向量检索（精准命中）
- **父块**：1024 tokens，提供完整上下文给 LLM（答案质量）
- **工作原理**：检索时匹配小粒度子块，生成答案时使用大粒度父块

**预期效果**：
- 召回率：80% → 90%+
- 答案完整度：提升 30%+
- 用户体验明显改善

**技术实现**：
```python
from langchain.retrievers import ParentDocumentRetriever
from langchain.storage import InMemoryStore  # 生产环境改用 Redis

# 子块切分器（用于检索）
child_splitter = RecursiveCharacterTextSplitter(
    chunk_size=256,
    chunk_overlap=30,
    separators=["\n\n", "\n", "。", "；", " "]
)

# 父块切分器（用于上下文）
parent_splitter = RecursiveCharacterTextSplitter(
    chunk_size=1024,
    chunk_overlap=100,
    separators=["\n\n\n", "\n\n", "\n"]
)

# 父子检索器
retriever = ParentDocumentRetriever(
    vectorstore=faiss_store,
    docstore=InMemoryStore(),  # TODO: 改为 Redis
    child_splitter=child_splitter,
    parent_splitter=parent_splitter,
)
```

### 父子分块工作原理

```
用户查询："差旅补贴标准"
    ↓
【步骤1】向量检索命中子块（256 tokens）
    "差旅补贴标准为 550 元/天"
    ↓
【步骤2】根据子块 ID 找到父块（1024 tokens）
    "第三章 差旅补贴管理
     第一节 补贴标准
     员工差旅补贴标准为 550 元/天，高管为 670 元/天。
     一线城市系数 ×1.2，二线 ×1.0，三线 ×0.8。
     具体执行细则参见附件 A。"
    ↓
【步骤3】将完整父块送给 LLM 生成答案
    ✅ 答案包含：基础标准 + 城市系数 + 执行细则
```

### 为什么父子分块更好？

**核心矛盾**：
- 小块检索准（精准命中关键词），但上下文不足（LLM 生成答案不全面）
- 大块上下文全，但检索容易漏（向量表征模糊）

**父子分块的破局之道**：

| 维度 | 固定窗口 (512 tokens) | 父子分块 (子 256 / 父 1024) |
|------|---------------------|---------------------------|
| **召回率** | 中等（可能切断关键句） | 高（小块精准命中） |
| **答案质量** | 差（上下文不足） | 优（父块提供完整信息） |
| **重复问题** | 多个重叠块返回相似内容 | 父块去重，唯一展示 |
| **存储成本** | 1x | 1.5x（值得） |
